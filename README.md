# Hybrid Hearts — Dr. Gamal Mansour (Cardiac Surgery)

Bilingual (Arabic RTL default / English LTR) website for Dr. Gamal Mansour's cardiac surgery practice,
**Hybrid Hearts**. It is a **fully static site**: the build produces plain HTML, CSS, JS and images that
any static host can serve — no Node.js server, database or API is needed at runtime.

---

## Quick start

```bash
npm install          # once
npm run dev          # local development → http://localhost:3000/ar/
npm run build        # production static export → ./out
npm run preview      # serve ./out locally exactly like a static host → http://localhost:4173
npm run check        # lint + type-check + build
```

Requires Node.js 20.9+ (built and tested with Node 26). Fonts are downloaded from Google Fonts **at build
time** and self-hosted in the output, so the build machine needs internet access; visitors' browsers never
contact Google.

---

## Deploying (static hosting)

1. **Set the production domain** (used for canonical URLs, hreflang, Open Graph and the sitemap):

   ```bash
   # macOS / Linux
   NEXT_PUBLIC_SITE_URL=https://www.your-domain.com npm run build
   # Windows PowerShell
   $env:NEXT_PUBLIC_SITE_URL="https://www.your-domain.com"; npm run build
   ```

   Without it, URLs fall back to the placeholder `https://hybrid-hearts.example`.

2. **Upload the *contents* of `./out`** to the web root of your host (cPanel `public_html`, Netlify,
   Cloudflare Pages, GitHub Pages, S3 + CloudFront, Nginx, Apache …).

3. That's it. Notes:
   - Pages are exported as folders (`/ar/about/index.html`) so clean URLs like `/ar/about/` work on any
     host **without rewrite rules**. **No SPA fallback is needed** — every route is a real HTML file.
   - `out/404.html` is the branded bilingual not-found page. Most hosts pick it up automatically; on Apache
     add `ErrorDocument 404 /404.html`, on Nginx `error_page 404 /404.html;`.
   - `/` is a small language gateway: English-preferring browsers go to `/en/`, everyone else to `/ar/`.
   - `out/robots.txt`, `out/sitemap.xml` and `out/manifest.webmanifest` are generated by the build.

### Windows build note

`npm run build` runs `scripts/fix-export-segments.mjs` after `next build`. It works around a Next.js 16
static-export bug **on Windows only** (segment-prefetch files are written into nested folders instead of the
flat file names the client requests, causing harmless-but-noisy 404s). On Linux/macOS it does nothing.

## Editing content

All text lives in `/content` — one typed file per page, each with `ar` and `en` versions (TypeScript
flags any missing translation):

| File | Contains |
| --- | --- |
| `content/site.ts` | Contact details, social links, locations, portrait, domain — **start here** |
| `content/common.ts` | Navigation and shared UI strings, emergency notice, disclaimers |
| `content/home.ts` | Home page copy |
| `content/about.ts` | About page copy, credentials, experience |
| `content/services.ts` | Service areas (title, summary, body, bullet points, image, related articles) |
| `content/articles.ts` | Heart Library articles (sections, bullets, key takeaways) |
| `content/videos.ts` | Published videos (YouTube IDs) and planned topics |
| `content/patients.ts` | Testimonials and FAQ |
| `content/contact.ts` | Contact page copy and WhatsApp composer labels |
| `content/pages.ts` | Services/articles page headers and the appointment CTA band |

**Adding…**
- *a video:* push `{ youtubeId, title, description, topic }` into `videos`. Playback uses a click-to-load
  `youtube-nocookie.com` embed (no YouTube requests until the visitor presses play).
- *a testimonial:* only with the patient's written consent — push into `testimonials`; it appears on the home
  and Reviews pages with a "verified" label.
- *an article:* add an object to `articles` with a unique `slug`; its pages for both languages, sitemap
  entries and metadata are generated automatically.
- *the portrait:* save it as e.g. `public/images/dr-gamal-mansour.webp` and set
  `site.portrait = { src: "/images/dr-gamal-mansour.webp", width, height }`.

## Architecture

- **Next.js 16 (App Router) with `output: "export"`**, `trailingSlash: true`, `images.unoptimized`.
  Every route is pre-rendered by `generateStaticParams` (`dynamicParams = false`); nothing renders per request.
  Not used (incompatible with static hosting): API routes, Server Actions, proxy/middleware, ISR, runtime
  image optimisation, Cache Components.
- **Routing:** `app/[lang]/…` is the root layout (sets `<html lang dir>`); `app/(root)` is the `/` language
  gateway; `app/global-not-found.tsx` is the bilingual 404.
- **i18n:** hand-rolled and dependency-free (`lib/i18n.ts`). The language switch links to the same page in the
  other language (all routes and article slugs exist in both).
- **Styling:** Tailwind CSS v4. All design tokens are in `app/globals.css` (`@theme`): official colours,
  derived crimson/plum scales, rose/lavender surfaces, shadows, easing, motion, plus utilities for surfaces
  (`surface-blush`, `surface-lilac`, `surface-dawn`, `surface-plum`, `surface-ember`), textures (`grain`,
  `dots`, `hatch`) and Liquid Glass (`glass`, `glass-dark`, `glass-edge`, `glass-edge-dark`, `sheen`) with
  opaque fallbacks where `backdrop-filter` is unsupported.
- **Typography:** Alexandria (headings, Arabic + Latin), IBM Plex Sans Arabic (Arabic body), Plus Jakarta Sans
  (English body). Arabic text is never letter-spaced.
- **Motion:** CSS only — hero entrance, reveal-on-scroll (a tiny IntersectionObserver adds `data-shown`;
  content is fully visible without JavaScript), scroll-driven hero parallax (progressive enhancement), smooth
  native `<details>` accordions. Everything respects `prefers-reduced-motion`.
- **Images:** pre-generated responsive WebP sizes in `public/images` (typed manifest in `lib/photos.ts`) with
  intrinsic dimensions and blur placeholders to prevent layout shift; below-the-fold images lazy-load.
- **SEO:** per-page titles/descriptions, canonical + hreflang (`ar`, `en`, `x-default`), Open Graph/Twitter
  cards (`public/og/og-default.jpg`), `sitemap.xml`, `robots.txt`, JSON-LD (`MedicalOrganization`,
  `BreadcrumbList`, `Article`) containing verified facts only.
- **Accessibility:** semantic landmarks and heading order, skip link, visible focus rings, `aria-current`
  navigation, native `<dialog>` mobile menu (focus moves in, Escape closes, focus returns, scroll locked),
  labelled social icons, keyboard-operable accordion and topic filter, WCAG-AA text contrast.
